# MY CITY TWIN

A 3D model of the Melbourne CBD that shows which approved developments are
changing the streets around you, and how their shadows move across the day and
the year.

Front end for **FIT5120 · Monash-FIT5120-TE01**, Iteration 1 — user stories
1.1 (approved developments) and 1.2 (sunlight impact).

---

## Running it

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # type-checks with `tsc -b`, then bundles to dist/
npx vitest run   # 85 tests
```

`npm run build` is the real type check. `tsc --noEmit` on the root config
checks nothing, because that file only holds project references.

## Deploying

```bash
npm run build
npx wrangler deploy
```

Static assets on Cloudflare Workers. There is no server-side code — see
"Why there is no API" below.

## What it does

| Screen | Story |
|---|---|
| Landing | Search the CBD by street or address |
| Discovery | The approved projects nearest a chosen place |
| Development | What one project is, and what changes where it stands |
| Sunlight | Its shadow through four seasons and the hours of the day |

## Data

Two endpoints on the team's staging API:

- `GET /api/building/footprints` — 4,443 roof-plane rows across 1,548 buildings
- `GET /api/development/footprints` — 133 components across 49 developments

Both are also committed under `public/data/` as a snapshot. The app draws from
the snapshot immediately and refreshes from the live API behind it, so a
sleeping staging instance costs a refresh rather than a blank screen. The
snapshot is a build input, not a source of truth — regenerate it by fetching
the two endpoints.

## Decisions worth knowing before changing anything

**Coordinates.** Everything is metres in a local frame: `+x` east, `+y` north,
`+z` up. three.js is Y-up, and the entire conversion lives in one `<WorldFrame>`
group. Nothing below it should know three.js is Y-up. Geometry is never
computed in latitude and longitude — at 37.8°S a degree of longitude and a
degree of latitude differ by a factor of about 1.27, which tilts every shadow
by a consistent, invisible amount.

**The sun.** `scene/solar.ts` is checked against 36 vectors generated by
pvlib's NREL SPA implementation, to within 0.1°. The three ways solar geometry
usually goes wrong — a northern-hemisphere azimuth convention, a hard-coded UTC
offset, and refraction mixed into a geometric figure — all produce shadows that
look entirely plausible on screen, and none survives that comparison. Melbourne
sits at 37.8°S: the sun transits **north** and shadows fall **south**.

**Massing.** Each source row is one roof plane, and 2,651 of the 4,443 start
above ground. Every plane keeps its own base; only the lowest plane of each
building is sunk to the ground plane. Extruding them all from the ground would
be simpler and would guarantee nothing floats, but measured against the data it
invents solid mass under 201 of them — and solids cast shadow.

**Nothing is ever dropped.** 45 rows disagree with themselves about their own
height, by up to 11.7 m. They render in a muted tone rather than disappearing:
a building taken out of the scene casts no shadow, and a missing shadow reads
to a resident as sunlight. Errors here have to fall on the pessimistic side.

**Why there is no API.** The Cloudflare Workers free plan allows 10 ms of CPU
per request, which rules out server-side ray casting — and makes it
unnecessary, because the browser already holds the mesh in order to draw it.
A time slider that made a round trip per tick would not be usable anyway.

**The street grid.** The backend carries no street data, and none is needed:
the streets are the gaps between the massing. Only the names were missing, and
their geometry was measured from the 133 development addresses, then moved onto
the carriageway by searching for the offset that crosses the fewest buildings.
Fitting the addresses alone lands on the frontages, half a block off.

**What the shadow narrative will not say.** The design's wording names
protected public spaces. There is no protected-space data — that is user story
1.3 — so the sentences state only what the geometry supports: which way the
shadow runs and how far. A named forecourt would be a claim about a real street
made on the strength of nothing.
