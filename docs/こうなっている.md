# MY CITY TWIN — 何がどう動いているか

日本語での構成説明。コード中のコメントは英語で書かれているので、その全体像をこちらにまとめる。

対象は Iteration 1、**User Story 1.1（承認済み開発）と 1.2（日照インパクト）**。
公開先 https://mycitytwin.com ／ ソース約 6,300 行 ／ テスト 130 件。

---

## 1. 一言でいうと

**メルボルン CBD の建物 1,548 棟を 3D で立て、承認済みの開発 49 件をその中に置き、
それぞれの影が一日と一年でどう動くかを見せるサイト。**

「高さ 214m の塔が建ちます」では住民に何も伝わらない。
**「あなたの立っている歩道から、冬の午後に 1 時間 20 分ぶん日が消えます」**まで言うのが目的。

---

## 2. 全体の流れ

```
バックエンドの API（Render）
        │  building/footprints    4,443 行 → 1,548 棟
        │  development/footprints   133 行 →    49 件
        ▼
   src/data/    受け取る・数値に直す・投影する
        ▼
   src/scene/   3D にする・太陽を計算する・影を落とす
        ▼
   src/ui/      Figma の画面をかぶせる
```

**バックエンドは「幾何を配る」だけで、計算は全部ブラウザの中**でやっている。
理由は Cloudflare Workers の無料枠が 1 リクエスト 10ms CPU しかないこと、
そして時刻スライダーを動かすたびにサーバーへ往復していたら使い物にならないこと。

---

## 3. データ層 — `src/data/`

### `api-types.ts` — API が実際に返す形

バックエンドの型定義。**数値が全部文字列で来る**ことも含めて、ありのまま書いてある。
ここより外側のコードは、この型を一切見ない。バックエンドが変わってもここだけ直せばいい。

### `model.ts` — アプリの中で使う形

投影済み・数値は数値。ここから先は緯度経度も文字列の数値も出てこない。

### `project.ts` — 座標の投影

WGS84（緯度経度）→ EPSG:7855（メートル）→ ローカル原点を引く。

**緯度経度のまま幾何計算をしてはいけない。** 南緯 37.8 度では経度 1 度と緯度 1 度の
実距離が約 1.27 倍違うので、**影が一定量だけ、目に見えない形で傾く。**

### `adapter.ts` — API の形をアプリの形へ

ここに 2 つの重要な判断がある。

**① 各屋根面は「自分の底」から押し出す**

元データは 1 行 = 1 枚の屋根面で、**4,443 行のうち 2,651 行（60%）は地面に接していない。**
全部を地盤から押し出せば浮遊は防げるが、実データで測ったところ **201 枚の下には
本当に何も無かった。** そこに柱を捏造すると、**存在しない影が落ちる。**

なので各面は自分の底から押し出し、**各建物の最下面だけを地面まで沈める**。

**② 矛盾する行を消さない**

45 行で、高さの計算経路 2 つが最大 11.7m 食い違う。**それらは消さずに、くすんだ色で描く。**

> 建物を消すと影が消える。**影が消えた結果は「日が当たる」**なので、
> 欠測が楽観側に倒れる。誤差は悲観側に倒さなければならない。

### `useCityModel.ts` — 読み込み

**同梱スナップショット → 即描画 → 裏で本番 API を叩いて差し替え。**

バックエンドは Render の無料プランでスリープする。冷えた状態からの初回は 1 分近くかかる。
**デモの最中にそれを待つわけにはいかない。** スナップショットがあれば、
サーバーが寝ていても画面は出る。

### `fetchWithProgress.ts` — 進捗バー

建物データは 4.8MB。**タイマーではなく実バイト数**でバーを進める。
ネットワークが止まればバーも止まる。`Content-Length` が無いときは
**偽の分母を作らず**不定形バーに切り替える。

### `urlState.ts` — 状態を URL に

```
?view=sunlight&dev=X0015700&d=2026-06-21&t=900&at=-532.4,-198.1
```

見ている画面・開発・日付・時刻・**測った地点**が全部入る。
**リンクを送れば相手に同じ画面が開く。** これが Story C.1（ログイン無しで戻れる）の中核。

## 4. 3D 層 — `src/scene/`

### `frame.ts` — 座標系の規約（最重要）

```
アプリ全体:  +x 東 / +y 北 / +z 上（メートル）
three.js:    Y が上
```

**この変換は `WorldFrame` という group ひとつだけで行う。** その内側では three.js が
Y-up であることを誰も知らない。外側にいるもの（カメラ・街路名・ピン）だけが `enuToWorld` を呼ぶ。

**この境界は 2 回破って 2 回バグを出した。** 街路名が道路の裏で裏返り、
測定マーカーが垂直に立った。どちらも**型では捕まらない**（両方とも数値 3 つなので）。
今は `frame-boundary.test.ts` が機械的に検査している。

### `solar.ts` — 太陽の位置

`astronomy-engine` を使い、**pvlib（NREL SPA）が生成した 36 サンプルと 0.1 度以内で一致**
することをテストで確認している。

太陽計算が壊れる典型は 3 つあり、**どれも画面上はまったく自然に見える。**

| 罠 | どう防いだか |
|---|---|
| **北半球の方位規約** | 南中で方位 0 度（真北）、影は南。テストで固定 |
| **UTC オフセットのハードコード** | 6月は +10、**12月は +11**。IANA ゾーンから毎回引く |
| **大気差の混入** | 幾何高度を使う。見かけ高度との差もテストで検査 |

日付は自由に選べる（`SimulationDate`）。四季のボタンは同じ日付へのショートカット。

### `sun.ts` — 方向ベクトルと影の長さ

高度・方位 → 東西南北の単位ベクトル。影の到達距離 `height / tan(altitude)`。

### `massing.ts` — 建物を立てる

フットプリントのポリゴンを押し出す。**中庭（穴）はそのまま穴として扱う** —
塞ぐと存在しない質量が増え、質量は影を落とす。

**4,443 個を個別のメッシュにすると毎フレーム 4,443 回の描画命令**になるので、
マテリアル単位で 1 つに結合している。

### `sunlightAt.ts` — 「ここで何分失うか」

**Story 1.2 が本当に求めている数字。** 3D で影が動くのを見せるだけでは、
「20 分だけ横切る影」と「午後ずっと居座る影」の区別がつかない。

**計算方法：** 太陽へ向かう光線を上へ辿ると、水平位置は直線を描く。
だから「そのパーツの底と屋根の間で引いた線分」がフットプリントと交わるかを見れば、
光線が塊を通るかが**厳密に**分かる。レイマーチより速く、しかも正確。

**この開発だけを判定する。** 街全体と地形が正しくないと絶対的な日照時間は名乗れないが、
**差分なら正しく言える。** そしてストーリーの問い（*この開発が日照をどう変えるか*）に
直接答えるのも差分の方。画面にもその但し書きを出している。

> テストで一番効いているもの：**北側の点はどの季節でも 1 分も失わない。**
> 南半球では太陽が天頂より南に来ないので、北側に影は原理的に落ちない。
> 半球を取り違えていれば、ここだけが落ちる。

### `streets.ts` / `Roads.tsx` — 街路と道路

**ERD に道路データは 1 行も無い。そして必要ない** — 道路は建物と建物の**すきま**だから。
足りないのは名前だけだった。

**街路名の位置は、133 件の開発案件の住所から測った。** 主軸を当てると
**縦街路 70 度・横街路 160 度**という Hoddle Grid が数字で現れる。

ただし住所は「通りに面した**建物**」なので、当てはめた線は車道でなくファサード側に寄る。
**Queen Street の名前が屋根の上に乗っていた**のはこれが原因。
そこで**建物に当たらないオフセットを探し直した**（被覆 0.49 → 0.00）。

道路の**面**はさらに一段進めて、**街路の帯から建物を引き算**している。
帯のまま描くと **15%（小路は 40%）が建物の下**に潜っていた。引き算後は **0.03%**。

### `Ground.tsx` — 地面

縁が背景色へ溶ける。**建物データは Hoddle Grid で終わり、その外には本当に何も無い。**
四角く切れていると「世界の終わり」に見えるが、溶けていれば「分かっている範囲の終わり」に見える。
これは事実の方。

### `SunLight.tsx` / `SunArrow.tsx` — 影

平行光源をシャドウマップで落とす。**影カメラは街全体を覆い、街の中心に置く。**

> 一度、注目対象を中心にして「平面の対角線の半分」で囲っていた。
> 低い太陽では街の 270m の高さが横方向に回り込むので、**冬の午後——
> この製品が答えるべき一番肝心な場面で——影が途中で切れていた。**
> いまは **3 次元**対角線の半分で囲っている。

矢印は**地面**に描く。画面上に置くと**ひとつのカメラ角度でしか正しくない**（回すと嘘になる）。
長さは影の到達距離そのもの。装飾ではなく計測。

### `narrative.ts` — 平易な言葉

```
At 15:00
The tower's shadow runs south-east for about 620 m.
```

**Figma の文面はそのまま使えなかった。** 「the protected area」「the forecourt」と
**保護対象の公共空間を名指し**しているが、そのデータは Story 1.3 で、**テーブルすら存在しない。**

架空の広場をでっち上げれば見た目は一致するが、**根拠ゼロの主張を実在の街路について
住民に見せることになる。** なので幾何から言えることだけを述べている。
「protected」「forecourt」「plaza」を出力しないことをテストで固定してある。

## 5. 画面 — `src/ui/`

Figma の 4 画面。すべて 3D の上に浮かぶパネルで、**街が全面で覆われることはない**
（説明対象がガラスの向こうにあるので）。

| 画面 | 中身 |
|---|---|
| **Landing** | 検索（実データ 49 件に効く） |
| **Discovery** | 選んだ場所と、**距離順に近い 3 件**（実測 m） |
| **Development** | 状態・高さ・構成・用途。「何が変わるか」は**実データから生成** |
| **Sunlight** | 日付・時刻スライダー・太陽方位・影の説明・**地点クリックで数値** |

**Focus Mode** — UI が全部消えて 3D だけになる。Esc で戻る。
このとき**シーンのクリックも止める**：パネルが消えているのに
受光点や選択対象が変わってしまうと、何が起きたか分からない。

**色は「何ができるか」を示す。** 押せる開発は濃い緑、押せないときは淡い緑。
**答えの返らない誘いを出すのは、誘いが無いより悪い。**

## 6. テスト 130 件が何を守っているか

このプロジェクトのバグは、**ほぼ全部が「画面上は自然に見える」タイプ**だった。
だからテストは「見た目では気づけないもの」に集中している。

| ファイル | 守っているもの |
|---|---|
| `solar.test.ts` | 太陽 36 サンプルが 0.1 度以内。南半球・DST・大気差 |
| `sunlightAt.test.ts` | **北側は 1 分も失わない**。夏至の日照が窓に収まる |
| `sun-arrow.test.ts` | **矢印が太陽の方を向くことはあり得ない**（方位 24 通りで内積 −1） |
| `frame-boundary.test.ts` | 座標変換の境界。**2 回破ったので機械的に検査** |
| `road-surface.test.ts` | 道路が建物の下に潜っていない |
| `streets.test.ts` | Bourke Street が原点付近。ブロック間隔 200m |
| `city-model.test.ts` | 4,443 行が 1 行も消えていない。45 行が印付きで残っている |
| `segmented.test.ts` | 選択で寸法が変わらない（太字の幅を常に確保） |
| `simulation-date.test.ts` | 日付が 1 日ずれない（`new Date()` を避けた理由） |

**中身の無いレイヤーを操作できるようにするより、鍵がかかっている方が正直**なので、
Figma に名前があるものは名前だけ出して無効化している。

## 8. バックエンドへ伝えるべきこと

**高さの計算経路 2 つが食い違う行が 45 件ある**（最大 11.7m）。

```
footprintMinElevationAhdM − structureMinElevationAhdM ≠ relativeBaseHeightM
```

1% なので致命的ではないが、**まだ Thanh と Will に伝えていない。**

## 9. デプロイ

```
npm install
npm run build      # tsc -b で型検査してからバンドル
npx vitest run     # 130 件
npx wrangler deploy
```

**`npm run build` が本当の型検査。** ルートの `tsconfig.json` は参照だけを持つ形式なので、
`tsc --noEmit` は**何も検査せずに素通りする**（一度これで 3 件のエラーを見逃した）。

デプロイには `vananhpham` アカウントで **`Workers Editor` 以上**のロールが必要。
`Domain Administrator` だけでは弾かれる。
